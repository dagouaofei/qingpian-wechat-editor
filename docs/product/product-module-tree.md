# 轻篇产品模块树

> **文档角色：** 轻篇完整一级产品模块树、候选二级模块、横向能力与模块边界的**当前生效事实源**（S12-STORY-003 · **DECISION-118**）。
>
> **上游事实源：** [`product-vision.md`](product-vision.md) · [`users-and-scenarios.md`](users-and-scenarios.md)（S12-STORY-002 · DECISION-117）
>
> **配套文档：** [`product-feature-catalog.md`](product-feature-catalog.md) — 功能目录口径、字段标准与各模块功能重点

---

## 1. Story 背景与目标

**S12-STORY-003** 的目标是将 **S12-STORY-002** 已确认的轻篇产品愿景、目标用户、核心场景与系统边界，进一步整理为**完整产品模块树**与**产品功能目录**，为后续 User Story Map、Product Backlog、Release Planning 和 Sprint Planning 提供稳定输入。

### 1.1 本 Story 明确不做

- 本 Story **不决定** Release 2 具体范围；
- **不决定**各模块开发优先级；
- **不把**全部功能拆成开发 Story；
- **不承诺**所有功能在同一 Release 或 Sprint 实现；
- **不开发**产品代码；
- **不设计**具体数据库、接口或技术架构；
- **不启动** S12-STORY-004；
- **不替代**后续 User Story Map、Product Backlog 和 Release Planning。

---

## 2. 模块树原则

### 2.1 三层规划口径

```text
功能目录 = 全景地图
Release Backlog = 当前阶段取舍
Sprint Backlog = 本轮执行承诺
```

### 2.2 结构原则

- **功能目录不是开发计划**；它描述轻篇完整产品应具备的能力全景，不等同于 Release 或 Sprint 承诺。
- **一级模块**按用户任务和业务职责划分，**不按**技术实现或代码目录划分。
- **一级模块**相对稳定；**二级模块**为当前候选结构，允许在后续 Story Map 与 Backlog 工作中调整。
- **实施顺序**必须由后续 Release Planning 和 Sprint Planning 决定，本 Story 中的「暂高 / 暂中 / 暂低」仅为粗略判断参考。

### 2.3 与 S12-STORY-002 能力域的关系

S12-STORY-002 确认了十个**一级能力域**。本 Story 将其落实为 **M01–M09 + M10 + M11** 共 **11 个一级产品模块**：

- M01–M09 与 S12-STORY-002 核心链路能力域一一对应；
- **M10** 对应原「协作与运营支持」中的工作空间与协作职责；
- **M11** 将**受众洞察与互动运营**从泛化运营支持中独立为一级模块，纳入完整产品范围（当前预估优先级靠后）。

## 3. 一级产品模块树

### 3.1 内容营销核心链路

| 编号 | 一级模块             | 核心职责                                                           |
| ---- | -------------------- | ------------------------------------------------------------------ |
| M01  | 品牌与知识中心       | 定义品牌、用户、表达规范、产品资料、专业知识和事实来源             |
| M02  | 灵感中心             | 收集外部内容和内部想法，识别趋势、竞品动态和内容空白，形成候选选题 |
| M03  | 内容计划             | 管理选题池、栏目、系列、内容策略、营销活动、内容日历、排期和任务   |
| M04  | 内容创作中心         | 将选题、知识和资料转化为大纲、文章、口播稿、视频脚本及多平台初稿   |
| M05  | 内容编辑与质量控制   | 负责改写、结构优化、品牌一致性、事实引用、合规、SEO/GEO 和审校     |
| M06  | 排版与视觉中心       | 负责文章编排、模板、样式、组件、图片、图表、品牌视觉和视觉质量治理 |
| M07  | 平台适配、发布与分发 | 负责公众号及其他平台的格式适配、复制导出、发布、分发和平台版本管理 |
| M08  | 内容资产中心         | 管理草稿、成品、历史文章、平台版本、内容片段、素材和复用           |
| M09  | 数据分析与内容复盘   | 分析文章、选题、栏目、平台和内容形式表现，并反哺后续内容策略       |
| M11  | 受众洞察与互动运营   | 收集评论、留言、用户问题和互动反馈，形成用户洞察并反哺内容生产     |

### 3.2 横向支撑模块

| 编号 | 一级模块       | 核心职责                                                             |
| ---- | -------------- | -------------------------------------------------------------------- |
| M10  | 工作空间与协作 | 提供工作空间、多品牌访问、成员、角色、权限、任务协作、审批和操作记录 |

### 3.3 编号说明

**M10** 作为横向支撑模块保留原编号；新增的受众洞察模块使用 **M11**，避免因展示顺序调整而反复重编号。

## 7. 抖音、多平台与多模态

1. **不建立**独立「抖音」一级模块。
2. 抖音作为**多平台**和**多模态**能力，分布在 **M02、M04、M07、M08、M09、M11** 等模块中。
3. **视频相关能力**包括（但不限于）：
   - 视频转文字；
   - 视频主题和观点提取；
   - 视频结构拆解；
   - 视频转灵感和选题；
   - 视频转公众号文章；
   - 文章转口播稿；
   - 口播稿转分镜；
   - 文章转短视频脚本；
   - 不同内容形态之间的改编。
4. 当前强调**「拆解、提取与再创作」**，不以机械复制他人内容为目标。
5. **多模态媒体制作中心**暂作为候选一级模块（C01），**不正式升级**；当前预估优先级靠后。

## 8. 模块边界

### 8.1 关键模块边界

| 边界对              | 划分原则                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| **M01 vs M08**      | M01 存放品牌规则与知识（创作依据）；M08 存放已生产的内容成果（草稿、成品、发布版本）           |
| **M02 vs M03**      | M02 解决「有什么值得写」（候选机会）；M03 解决「决定写什么、何时写」（正式选题、计划与任务）   |
| **M04 vs M05**      | M04 负责从 0 到 1 的内容生成与初稿；M05 负责编辑、优化、质量控制与发布前审校                   |
| **M06 vs M07**      | M06 负责好不好看、是否专业、是否符合品牌视觉；M07 负责能不能可靠复制、导出、发布并在平台中一致 |
| **M09 vs M11**      | M09 分析已发布内容的表现与复盘；M11 收集受众互动反馈并形成洞察反哺生产                         |
| **M10 vs M11**      | M10 提供工作空间、权限与协作基础设施；M11 聚焦受众互动与运营洞察                               |
| **M03-09 营销活动** | 归入 M03 内容计划；当前预估优先级靠后                                                          |

### 8.2 模块间关键事实源原则

以下原则是**当前候选**，不应阻止后续发现更合理边界后的调整：

1. **品牌规则和品牌知识**的正式事实源在 **M01**。
2. **候选内容机会**的正式事实源在 **M02**。
3. **正式选题、排期和内容任务**的事实源在 **M03**。
4. **文章和内容成果**的正式事实源在 **M08**。
5. **模板、样式和 Variant** 的正式事实源在 **M06**。
6. **平台账号、发布配置和发布结果**的正式事实源在 **M07**。
7. **内容表现数据和复盘记录**的正式事实源在 **M09**。
8. **受众反馈、用户问题和互动洞察**的正式事实源在 **M11**。
9. **成员、角色和访问权限**的正式事实源在 **M10**。

## 9. 与 Release Planning 的关系

- 本模块树描述轻篇**完整产品**应具备的结构，**不等于** Release 2 或任何单一 Release 的交付清单。
- Release Planning 从模块树与功能目录中**选取**当前阶段要实现、完善或验证的能力子集。
- Sprint Planning 从 Release Backlog 中**选取**本轮可交付的工作项。
- **S12-STORY-007** 将把 Release 1 历史能力映射到本模块树；**S12-STORY-008** 将基于本结构规划 Release 2 路线。

## 10. 当前优先级说明（非开发承诺）

- 本 Story 中的「暂高、暂中、暂低」只是当前粗略判断，**不构成** Release 或 Sprint 承诺。
- **M11** 受众洞察与互动运营已纳入完整产品范围，但**当前预估优先级靠后**。
- **C01** 多模态媒体制作中心为候选一级模块，**当前预估优先级靠后**。
- **M03-09** 营销活动与内容项目归入 M03，**当前预估优先级靠后**。
- 抖音相关能力已纳入完整产品方向，**不建立**独立抖音一级模块。
- SEO、GEO、AI、自动化均作为功能方向或横向能力，**不单独设**一级模块。
